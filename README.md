# Xperia Timelapse

面向 **Sony Xperia PRO-I** 的 Android 延时摄影应用。支持两段式实体拍摄键、镜头快捷切换、白平衡与 EV 调节、自动黑屏和锁屏后持续拍摄。延时任务停止或完成后，自动合成视频、校验并保存到相册；默认在保存成功后清理本任务原片。

当前版本：**0.5.21**（versionCode 26）。使用 Kotlin、Jetpack Compose、CameraX、Camera2Interop 和 Android 原生视频编码。最低 Android 10；主要真机验证设备为 Sony PRO-I XQ-BE72 / Android 13，其他设备的镜头、实体按键、编码器和后台行为以实际支持为准。

## 功能概览

| 功能 | 当前行为 |
| --- | --- |
| 拍照 | 拍摄 JPEG 或 RAW / DNG，自动保存到相册 |
| 定时拍照 | 立即拍摄一张，不等待间隔或旧倒计时 |
| 延时拍摄 | 按间隔拍摄照片，以总张数或总时长结束 |
| 快捷间隔 | 拍摄界面直接选择 1 / 5 / 10 / 30 / 60 秒 |
| 自定义间隔 | 1～3600 秒；总张数 1～100000，或总时长 1～1440 分钟 |
| 两段式实体键 | 半按中心对焦；全按并松开开始，再次全按停止并保存 |
| 镜头切换 | PRO-I 提供 0.7x、F2、F4、2.1x、前置；菜单可查看其他公开镜头 |
| 点击对焦 | 点击实际取景画面中的位置对焦，显示对焦圈与结果 |
| 白平衡 | 自动与当前镜头支持的预设，直接作用于相机 |
| EV | 按镜头支持的范围、步长调节，提供滑块、加减和重置 |
| 画面稳定 | 延时拍摄可锁定曝光、对焦和自动白平衡 |
| 自动省电 | 开始实际拍摄 5 秒后黑屏，授权后 30 秒自动锁屏 |
| 视频输出 | MP4、尺寸和方向与照片一致、24 / 25 / 30 / 60fps，无音频 |
| 视频编码 | 默认优先 H.265，支持 H.264；符合条件时可用硬件 AV1 |
| 自动保存 | 停止或完成后自动合成、完整解码校验、保存相册 |
| 中断恢复 | 拍摄异常断电后，可在项目列表对仍保留照片的项目手动重新生成视频 |
| 原片清理 | 默认在视频校验、相册发布和元数据写入成功后删除本任务 JPEG |
| 项目管理 | 查看历史项目、分享 MP4、导出项目 ZIP |
| 自适应布局 | 竖屏操作区在底部，横屏操作区在右侧；文件和设置在快门下方 |

核心拍摄、合成和保存流程在手机本地完成。应用没有申请网络、麦克风或广泛存储访问权限。

## 构建与安装

### 开发环境

| 项目 | 版本 |
| --- | --- |
| JDK | 17 |
| Android SDK / compileSdk | 35 |
| targetSdk / minSdk | 34 / 29 |
| Gradle Wrapper | 8.9 |
| Android Gradle Plugin | 8.6.1 |
| Kotlin | 1.9.22 |
| Compose Compiler | 1.5.10 |
| CameraX | 1.4.2 |

克隆仓库后，可用 Android Studio 打开项目并配置 Android SDK。首次同步和构建需要下载 Gradle 与依赖。

```sh
git clone https://github.com/volsifly/xperia-timelapse.git
cd xperia-timelapse
```

GitHub 公开仓库：[volsifly/xperia-timelapse](https://github.com/volsifly/xperia-timelapse)。APK 可在 [Releases](https://github.com/volsifly/xperia-timelapse/releases) 下载。

在项目根目录创建本机专用的 `local.properties`，将 SDK 路径改成自己的安装位置：

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

构建、单元测试和静态检查：

```sh
./gradlew testDebugUnitTest assembleDebug lintDebug
```

Windows 使用 `gradlew.bat`。如果默认 Java 版本不是 17，请先将 `JAVA_HOME` 指向 JDK 17。依赖已经缓存时，可在命令末尾加 `--offline`。

### 安装到手机

debug APK 输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

手机启用 USB 调试或无线调试并授权电脑后安装：

```sh
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

多个设备连接时，使用 `adb -s <设备序列号> install -r ...` 指定设备。也可以将构建好的 APK 传到手机后安装。

仓库不包含发布签名或签名密钥。当前构建命令生成调试版；覆盖安装需要与已安装应用签名一致。更新前先停止拍摄并等待视频保存完成。

## 首次使用

1. 打开应用并允许相机权限，等待预览就绪。
2. Android 13 及以上允许通知权限，以便查看拍摄状态和通知中的停止入口。
3. 默认开启 30 秒自动锁屏。首次使用时，在系统页面启用“拍摄自动锁屏”；它仅申请锁定屏幕能力。也可在“设置 → 拍摄设置”关闭自动锁屏。
4. 选择镜头，对准拍摄对象。可点击画面或半按实体键对焦，再调整 WB 和 EV。
5. 选择拍照、定时或延时模式。延时可直接选快捷间隔，其他条件放在设置菜单中。
6. 点击屏幕快门，或全按并松开实体拍摄键。正常结束或停止后等待合成、校验和保存完成。
7. 点击快门下方“文件”打开相册；“设置 → 项目列表”查看应用内项目和导出功能。

首次点击快门触发锁屏授权时，授权成功后才开始拍摄。拒绝授权不会开始该次拍摄；可完成授权，或关闭自动锁屏后再次开始。

全新安装的默认延时条件为 **每 2 秒拍摄 100 张**，照片长边为 **1920 像素**，视频为 **30fps、自动优先 H.265、标准画质**。升级会保留已保存的个人设置。

## 拍摄界面与操作

### 三种拍摄模式

- **拍照**：立即拍摄一张照片，自动保存到相册，保留项目原片。
- **定时**：按下快门立即拍摄一张照片，自动保存到相册，保留项目原片。
- **延时**：按间隔持续拍摄，可按总张数或总时长结束。至少两张照片时自动合成视频；只有一张时按照片保存。

“设置 → 拍摄设置”可配置自定义间隔、总张数、按时长结束，以及曝光、对焦和白平衡锁定。“设置 → 视频输出”配置成片规格和原片清理。

### 屏幕快门与实体键

| 操作 | 空闲时 | 拍摄或暂停时 | 停止或合成时 |
| --- | --- | --- | --- |
| 屏幕圆形快门 | 开始当前模式 | 暂停 / 继续 | 等待处理 |
| 屏幕停止按钮 | 不显示 | 停止并保存 | 合成期间可取消合成 |
| 实体键半按 | 对画面中心自动对焦 | 保留现有焦点 | 不执行对焦 |
| 实体键全按并松开 | 开始当前模式 | 停止并保存；倒计时阶段也可停止 | 不执行动作 |
| 通知中的停止入口 | 不显示 | 停止拍摄 | 合成期间可取消合成 |

实体键全按不会变成暂停键。长按重复事件只在一次完整按压结束时触发一次；取消的按压或窗口焦点丢失后未完成的按压不会触发。音量键保留系统功能。

应用内的黑屏界面仍支持全按停止；真正系统锁屏之后，需要先解锁回到应用。没有实现全局按键接管或通过实体键从锁屏直接启动本应用。

### 镜头与对焦

PRO-I 的 F2 与 F4 是同一主摄的两个光圈请求；0.7x 和 2.1x 是按公开镜头能力显示的快捷标签。镜头能力页提供硬件等级、尺寸、像素、快门和 ISO 范围、对焦、锁定能力、JPEG / RAW 输出能力以及帧率等信息。

空闲时点击取景画面，对点击位置请求自动对焦；半按实体键对中心请求自动对焦。成功显示合焦提示，失败会提示换个位置。预览采用完整画面适配，黑边不参与点击对焦；不支持自动对焦的镜头会提示。

拍摄或合成期间禁止切换镜头，拍摄中不通过点击或半按改变焦点。点按对焦只调整 AF 区域，不改变曝光测光区域。

Sony 预览结果可能在请求 F4 时仍报告 F2。项目元数据分别记录请求光圈和预览测量值，不把预览值当成实际成片光圈的独立证明。

### 暂停、继续与停止

暂停会等待当前照片保存完毕，保留相机和锁定参数。总时长按实际运行时间计算，暂停时间不计入。

停止同样会等待正在保存的照片完成，再进入保存或合成阶段。请等待“视频已保存到相册”，不要在编码或校验过程中强制结束应用。

拍摄期间模式、WB、EV、镜头及配置锁定，仍可查看菜单。旋转屏幕会更新预览布局；照片输出方向在一段任务中保持固定，避免同一序列中方向变化。

## 白平衡、EV 与参数锁定

### 白平衡 WB

取景区的镜头按钮上方点击 `WB`，选择自动、日光、阴天、阴影、白炽灯、荧光灯、暖荧光灯或黄昏。**只显示当前镜头支持的预设**，不是所有设备都会提供完整列表。

选择直接写入相机白平衡模式，立即影响预览和后续照片。当前不提供 Kelvin 色温输入或手动 RGB 增益。

### 曝光补偿 EV

点击 `EV` 打开滑块，也可用加减按钮按相机最小步长调整，或“重置为 0”。正值使画面更亮，负值使画面更暗。

PRO-I 实测支持 **−2～+2 EV**，步长为 **1/12 EV**。界面显示到小数点后一位，实际参数按设备步长保存；例如显示 `+1.1` 时，实际值可能是 `+1.0833334`。其他镜头按自身范围和步长限制。

### 延时参数锁定

| 设置 | 行为 |
| --- | --- |
| 锁定曝光 | 支持时固定预览测得的快门和 ISO，否则使用设备支持的 AE 锁 |
| 锁定对焦 | 保留当前对焦距离；数值单位为屈光度 |
| 锁定白平衡 | 自动 WB 时使用设备支持的 AWB 锁；预设 WB 持续指定所选模式 |

开始拍摄前会等待 WB 和 EV 的实际预览反馈，并等待测光、对焦等状态稳定后冻结参数。锁定曝光使用的是调节 EV 后的测量值。设备不支持的锁定不会强行写入，是否实际启用记录在 `metadata.json` 中。

拍照和定时模式不执行延时的曝光 / 对焦 / AWB 锁定，但沿用已选择的 WB 和 EV。当前没有手动输入 ISO 或快门时间的界面；RAW / DNG 可在拍摄设置中开启，高帧率能力仍仅供检测。

## 哪些设置会保存

设置修改后自动保存到手机本机偏好，正常退出、进程重启和手机重启后会重新读取。覆盖安装且不清除应用数据时保留；卸载或清除应用数据会删除这些设置。

| 项目 | 是否保存 | 说明 |
| --- | --- | --- |
| 拍摄模式 | 是 | 拍照 / 定时 / 延时 |
| 间隔、总张数、总时长与结束方式 | 是 | 快捷选择和菜单修改均保存 |
| 旧定时倒计时 | 不再使用 | 保留旧偏好数据，但不影响开始拍摄 |
| 白平衡模式、EV | 是 | 打开相机或切换镜头时重新应用 |
| 曝光、对焦、白平衡锁定开关 | 是 | 保存开关，不保存上次传感器测量值 |
| 拍摄图像大小、视频帧率、编码、画质 | 是 | 运行时仍需检测编码器是否可用 |
| 删除原片开关 | 是 | 默认开启 |
| 自动黑屏、自动锁屏、指示灯开关 | 是 | 均默认开启；锁屏授权由系统独立管理 |
| 镜头选择及 F2 / F4 | 否 | 服务存活期间可保留；重新创建相机服务时优先主摄，PRO-I 优先 F2 |
| 点击对焦位置、焦点测量值 | 否 | 下次拍摄重新对焦或读取当前状态 |
| 未完成的拍摄任务 | 不自动恢复 | 进程被终止后不在后台擅自重开相机 |

新镜头不支持已选 WB 时会回到自动；EV 会吸附到新镜头支持的步长并限制范围，调整后的值会保存。

## 自动黑屏、锁屏与硬件指示灯

### 拍摄时序

| 时间点 | 行为 |
| --- | --- |
| 开始实际拍摄 | 相机前台服务运行，持有 CPU 部分唤醒锁 |
| 5 秒 | 自动显示低亮度黑屏，隐藏系统栏 |
| 30 秒 | 已授权且开关开启时，调用系统能力真正锁屏 |
| 锁屏后 | 拍摄服务和 CPU 唤醒锁继续运行 |
| 停止或完成 | 取消未触发的锁屏计时，完成保存后释放资源 |

两个时间点从进入实际拍摄状态计时，不包含相机准备和倒计时。暂停会取消未到期的自动锁屏，继续拍摄重新计时 30 秒；每段持续拍摄只触发一次锁屏。

5 秒后的黑屏是应用画面，屏幕还保持唤醒；30 秒后的锁屏是系统状态。可双击应用黑屏或按返回键恢复界面，也可在拍摄设置中分别关闭这两个功能。恢复界面不会立即重复锁屏。

自动锁屏需要系统设备管理员授权，仅申请 `force-lock`，没有申请清除数据或密码管理策略。如需撤销，使用系统的设备管理页面；若系统阻止卸载，先停用该授权。

前台服务和唤醒锁已在 PRO-I 短任务中验证能够支持锁屏拍摄，但长时间运行仍受系统后台策略、驱动、温控和设备状态影响。进程被强制结束或系统终止后不会自动续拍。未测量省电百分比。

### 硬件指示灯

应用通过静音通知向系统请求灯光：拍摄橙色、暂停黄色、合成蓝色，结束后取消。使用的是硬件通知灯请求，没有使用相机闪光灯或屏幕亮点代替。

PRO-I / Android 13 在真正熄屏后才可能显示该通知灯。系统实际使用的闪烁节奏曾测得为约 100ms 亮、6000ms 灭；普通应用无法保证橙色常亮。屏幕唤醒、通知权限、勿扰、充电灯和其他通知可能影响显示。

已记录熄屏时灯驱动的橙色输出请求，但驱动记录不等同于人工确认灯珠持续点亮。直接灯控制接口在该设备上需要系统特权，当前应用不请求该特权。

单张和定时模式均在按下快门后直接请求拍摄，不使用延时间隔或旧倒计时，也不等待延时拍摄的参数锁定。已在预览阶段生效的白平衡、EV 和光圈不会在单张快门流程中重复提交并等待确认。相机硬件曝光、RAW 格式切换和写盘仍有必要耗时，与间隔参数无关。

## RAW 与 Log / 胶片风格

拍摄设置可开启“保存 RAW / DNG”。支持情况按当前镜头和 CameraX 实际输出格式查询，未支持时禁止开始并提示切换镜头或关闭 RAW，不会用 JPEG 冒充 RAW。

- 拍照和定时拍照只保存 DNG，保持原始传感器尺寸与拍摄方向。
- 延时模式同时捕获 DNG 和 JPEG。DNG 通过校验后保存到相册；JPEG 用于生成视频，按所选长边缩放并应用色彩效果。
- DNG 不应用缩放、Log、胶片调色，视频成功后也不会自动删除。关闭 RAW 时沿用原有 JPEG 清理设置。
- RAW 与视频各自发布，视频编码失败时 RAW、JPEG 均保留。相册能否展示 DNG 缩略图取决于相册软件，原片也保存在项目中，可导出 ZIP。
- DNG 体积较大，合成视频仍通过相机同时输出的 JPEG，当前不包含自行解码 RAW 传感器数据并调色的视频流程。

取景界面点击“色彩”选择自然、软件 Log、经典负片、经典正片、鲜艳反转片、影院柔色、细腻黑白，并调节 0～100% 强度。选择跨重启保存，拍摄期间禁止更改。同一效果先写入 JPEG，合成时不重复调色。

软件 Log 是对相机 JPEG / 预览 sRGB 输出施加的自定义平坦曲线，**不是 Sony S-Log、F-Log 或原生 10-bit Log**，不能恢复相机输出中已裁掉的高光。内置胶片预设为项目自研色彩配方；也可从风格面板导入自己的纯 3D `.cube` 文件。


### 点按对焦与区域测光、快门流程（0.5.19）

点按取景画面通过同一个 PreviewView MeteringPoint 设置 AF 和 AE 区域；半按拍摄键使用画面中心。保留已有横竖屏映射和黑边过滤。先确认镜头支持区域 AE，明确提示不支持的情况，不以全画面测光冒充点测光。AF 请求完成后继续等待应用该区域的更新帧和 AE 收敛结果，随后恢复并确认所选 F2/F4，同时保留 EV 与白平衡设置。

重复点按会取消旧任务，光圈恢复完成后再执行新点，避免旧任务的清理覆盖新曝光。对焦测光中按快门只排队一次，完成并恢复所选光圈后再拍摄；停止会清掉未执行请求。此等待属于用户刚触发的测光，而非间隔计时。

原先“已发出拍摄请求”提示在日志写盘后更新，现改为先更新提示再异步记录日志。单张 / 定时在请求拍摄前不再等待项目参数的两次 fsync，参数与首张成片元数据在拍照后一起持久化；连拍的参数锁定和元数据准入保持原有行为。LUT 的三通道共用八顶点插值索引和权重，减少重复计算，保存结果仍使用同一套 LUT。

参数文件改为后台有序写队列：每次更新先取得不可变快照，同一个文件按顺序 fsync 和原子替换，不同文件的队列可并行。诊断日志使用独立队列，不拖住拍摄请求和阶段提示。结束时参数保存与相册复制 / 校验并行，但“已保存”状态仍等待照片验证发布与必要元数据落盘；写盘错误向结束流程传播，不吞掉保存失败。视频验证、相册发布与删除原图之间的持久化校验屏障继续保留。回归测试覆盖慢参数写入不阻塞日志、快照顺序及磁盘失败传播。

构建与测试只能验证软件路径；当前手机未连接，尚未测量 Sony 实际快门到曝光或保存的耗时，不能保证达到系统相机的速度。

### PRO-I 主摄 F2 / F4 控制（0.5.18）

F2 和 F4 是同一主摄的可变光圈，切换时不重开镜头。旧版虽然设置 `LENS_APERTURE`，但仍启用系统 AE；[Android 官方契约](https://developer.android.com/reference/android/hardware/camera2/CaptureRequest#LENS_APERTURE)明确说明 AE 开启时光圈会被自动曝光算法覆盖，因此按钮切换不能证明物理光圈已变。

新版在可变光圈镜头上读取当前测光的快门、ISO 和实际光圈，按平方比补偿曝光（F2→F4 为 2 档），随后设置 AE OFF、快门、ISO、帧时长和所选光圈。切换阶段等待相机结果回报目标 F 值且镜片不再移动；未确认则回滚并提示，不将 F4 伪装成成功。固定光圈镜头仍保持系统自动曝光。EV 在手动控制时按曝光倍率调整，不依赖已经关闭的 AE 补偿。

**使用限制**：可变光圈模式采用“测光后固定曝光”，场景亮度变化时点按画面对焦即可按点击位置重新测光，半按实体拍摄键则对中心点对焦并测光；也可调整 EV。不再提供独立“重新测光”按钮。对焦测光会短暂恢复 AE，再回到所选光圈，期间可能发生正常的光圈动作；拍摄后不自动执行。它不是连续自动的光圈优先曝光。可变光圈镜头关闭 JPEG ZSL，防止使用切换前的旧光圈缓存帧；切换、测光均在取景阶段完成。

保存后读取照片 / DNG 的真实 EXIF FNumber，显示“照片已保存 · 实际 F…”；不改写 EXIF 冒充选中值。不一致时明确提示。每帧 FNumber 写入项目 `captured_apertures`，日志同时记录请求和成片光圈。仍需要 Sony 真机验证物理叶片、RAW / JPEG 成片和 AE OFF 时的对焦行为。

### 拍后闪屏 / 镜头重复动作（0.5.17）

单张和定时成功完成（或正常停止）时保持同一相机会话，保存完成后继续取景，不关闭再开启、不重新提交参数或自动恢复焦点。延时结束或拍摄异常仍释放相机；需要重开同一镜头时沿用当前 JPEG / RAW 和 ZSL 策略，避免先打开默认 JPEG 再由格式准备流程重建一次。关闭操作幂等，防止结束处理重复解绑。

此修改去掉了代码中确定存在的重复重启路径；实际 Sony 镜头动作和画面闪动需真机复测，正常的硬件自动对焦与可变光圈动作不保证完全静音。

### 单张快门延迟排查（0.5.16）

RAW / JPEG 格式和单张拍摄策略在取景阶段准备完成，快门按钮只有在当前镜头、模式和 RAW 组合准备好后才能开始。以前 RAW 在按快门后重新绑定相机、提交光圈与白平衡 / EV，并可能等待点按对焦（最长 8 秒）；现在这些操作移到按快门之前。必要的格式准备期间界面显示“正在准备相机”。

单张 / 定时 JPEG 在 CameraX 报告支持时启用零快门延迟（ZSL）并关闭闪光灯，使用接近快门时间的缓存帧。RAW 不支持这条 JPEG 缓存路径，继续使用最小延迟拍摄。延时连续拍摄保持原来的最小延迟策略，避免使用锁参数前的旧缓存帧。参考 [CameraX ImageCapture 官方说明](https://developer.android.com/reference/androidx/camera/core/ImageCapture)。

单张界面区分“已发出拍摄请求 / 相机已开始拍摄 / 照片已拍下，正在处理色彩 / 正在保存到相册”，不再显示无意义的“下一张”倒计时。项目 `capture.log` 中记录快门到 prepared、scheduler_start、request、capture_started、camera_saved、processed 的累计毫秒，系统日志标签为 `XperiaShutter`。由此可以区分应用准备、CameraX / 手机曝光，以及 JPEG 调色与写盘耗时。`capture_started` 是 CameraX 回调时间，不等于精确传感器曝光时间。

这些改动通过软件构建与测试，但当前未连接手机，不能据此确认 Sony 真机的快门延迟已经消失。ZSL 是否实际启用、RAW 的传感器耗时、LUT 成片处理时间需要设备日志验证。

### 导入 3D LUT（0.5.20）

在取景界面点“色彩”，选择“导入 .cube 文件”从系统文件选择器添加 LUT。支持 Adobe Cube LUT 格式中的纯 3D LUT，`LUT_3D_SIZE` 为 2 至 65，可带 `TITLE` 和成对的 `DOMAIN_MIN` / `DOMAIN_MAX`；也接受 DaVinci Resolve 常用的 `LUT_3D_INPUT_RANGE`。不支持 1D LUT 或 1D+3D 混合文件；导入时会验证数据行数量、数值和输入范围，无效文件会显示错误。

导入的 LUT 转换为应用内部 8-bit sRGB 立方表，存入应用私有空间；选择和强度跨重启保存，可在风格菜单中删除。效果用于预览、处理后的 JPEG 和延时视频，不更改 DNG RAW。应用源码和安装包不附带第三方 LUT 内容；LUT 的创作与许可由导入者负责。

保存 JPEG 使用 CPU 三线性插值，Android 13 及以上预览使用 GPU 图集；视频采用已经处理的 JPEG。应用按 `.cube` 输入范围处理 0–1 RGB，不会自动识别或转换 LUT 对应的 Log 曲线、色域及传递函数。预览和成片也会受相机处理差异影响。

Android 13 及以上通过 AGSL 显示实时预览；更低版本只在保存的 JPEG 和视频中应用效果。预览使用相机预览流，与 JPEG 的曝光和色彩处理可能存在细微差异。预览 shader 失败会提示，最终照片仍通过独立色彩处理保存。

本版本构建和软件测试不等于 Sony PRO-I 的实际 RAW、GPU shader 和长期后台拍摄验证，需安装后分别验证支持的镜头、DNG 打开、色彩预览、两帧以上视频及 RAW 保留。

## 视频编码、分辨率与帧率

延时视频由原生 `MediaCodec` 编码、`MediaMuxer` 封装为 MP4。保存 JPEG 时应用拍摄方向，并按所选长边缩放，保留完整画面比例。视频直接采用照片实际宽高，不补黑边、不裁剪，也不另行改变视频尺寸。每次处理一张图片，不将整个序列同时解码到内存；视频无音轨。

### 输出规格

| 拍摄照片长边 | 4:3 横拍 / 竖拍示例 |
| --- | --- |
| 1280 | 1280 × 960 / 960 × 1280 |
| 1920 | 1920 × 1440 / 1440 × 1920 |
| 3840 | 3840 × 2880 / 2880 × 3840 |

成片帧率可选 24、25、30、60fps。它决定播放速度，**不是拍照频率**；拍摄间隔仍单独配置，照片大小在“拍摄设置”中调整；视频尺寸和方向跟随照片。序列方向在拍摄开始时固定，若照片序列尺寸不一致，停止合成并保留原片。

成片时长约为 `成功拍摄的照片张数 ÷ 输出帧率`。例如每 5 秒拍摄约 10 分钟，约得到 120 张照片；输出 30fps 时约为 4 秒。实际张数可能受拍照耗时、停止时间和错过时点影响。

### 编码选择与回退

| 选择 | 尝试顺序 |
| --- | --- |
| 自动 / H.265 | H.265 → H.264 |
| H.264 | 仅 H.264 |
| AV1 | AV1 → H.265 → H.264 |

运行时检测当前分辨率、帧率、码率和输入格式，优先使用硬件编码器。编码或校验失败可尝试后续格式；回退保持照片实际尺寸和所选帧率，不自动降低规格。全部失败时保留原片。

AV1 仅在 Android 14 及以上且存在满足当前规格的硬件编码器时开放；PRO-I / Android 13 不提供此路径。支持 AV1 解码不代表能够编码 AV1。

### 画质与目标码率

以下以 **1080p / 30fps** 为基准：

| 格式 | 节省空间 | 标准 | 高画质 |
| --- | --- | --- | --- |
| H.265 | 2 Mbps | 4 Mbps | 8 Mbps |
| H.264 | 4 Mbps | 8 Mbps | 12 Mbps |
| AV1 | 1.5 Mbps | 3 Mbps | 6 Mbps |

目标码率随像素数和帧率按比例缩放，最低 0.5 Mbps。例如标准 H.265 的 4K / 30fps 目标为 16 Mbps，4K / 60fps 为 32 Mbps。

实际体积和画质取决于画面与编码器。“节省空间”会降低目标码率；H.265 的默认目标码率为 H.264 的一半，不保证二者画质相同。

## 自动保存、原片清理与项目导出

### 保存位置

| 内容 | 位置 |
| --- | --- |
| 相册照片 | `Pictures/XperiaTimelapse` |
| 相册视频 | `Movies/XperiaTimelapse` |
| 应用项目 | `Android/data/com.xperia.timelapse/files/Pictures/XperiaTimelapse/<项目>/` |

外部应用专属目录不可用时，项目回退到内部目录。视频和照片通过 MediaStore 发布到相册，不要求手动选择目录。

主界面“文件”打开手机相册；应用内历史项目在“设置 → 项目列表”。相册是否按上述目录分组，取决于相册应用。正常延时的每张原片不单独发布到相册，避免删除项目原片后仍留下重复照片。

### 自动处理顺序

1. 结束当前照片的保存，写入任务状态。
2. 延时任务至少两张照片时合成视频。
3. 核对轨道格式、分辨率和时间戳，完整解码并检查帧数与照片数一致。
4. 将视频复制到 MediaStore 待发布条目，核对复制内容的 SHA-256 后发布。
5. 保存视频验证和相册发布的元数据。
6. 删除原片开关开启时，仅清理本项目顺序编号的 JPEG。

合成失败、保存失败或取消时不会开始正常的原片清理流程；已落盘原片可用于恢复。清理阶段若被强制终止，可能只保留部分原片，不能把进程中断视为自动恢复成功。

默认原片清理是永久删除。需要后期处理照片时，在开始前关闭“设置 → 视频输出 → 合成后删除原片”。

### 项目文件与导出

```text
<项目>/
├── frame_000001.jpg   # 拍摄期间的原始照片；成功清理后移除
├── frame_000002.jpg
├── metadata.json      # 设备、拍摄条件、状态、参数、视频和相册信息
├── capture.log        # 重试等运行记录，存在相关事件时生成
└── preview.mp4        # 自动合成的项目视频
```

元数据包含相机 ID、间隔、起止时间、照片数量、请求与测量参数、实际编码器、编码回退、分辨率、帧率、码率、完整校验状态、相册 URI 和原片删除情况。元数据通过临时文件、同步写入和原子替换更新。

项目列表可查看成片信息、分享 MP4、导出项目 ZIP。项目仍有至少两张 JPEG 且未生成视频时，会显示“生成视频”按钮，可用已保存的照片重新合成并保存到相册。ZIP 只包含当前项目仍存在的文件，无法恢复已删除原片。

项目视频和相册视频分别保存，自动清理 JPEG 不会删除项目的 `preview.mp4`。卸载会删除应用专属项目目录；需要保留项目元数据或原片时，先导出 ZIP。

## 常见问题

### 文件按钮和项目列表有什么区别？

文件按钮用于打开手机相册，浏览已发布照片或视频；项目列表用于查看应用内项目、成片详情和 ZIP 导出。文件入口失败时会显示错误提示，可从系统相册直接查看。

### 黑屏后拍摄是否还在继续？

应用黑屏和系统锁屏都不会主动停止正在运行的拍摄服务。可通过通知或解锁后的照片数量确认。若进程被系统结束，则不会自动恢复；长时间任务仍需检查电池后台限制和设备状态。

### 为什么没有橙色常亮灯？

灯光受系统控制。应用黑屏期间屏幕仍唤醒，系统可能抑制通知灯；真正熄屏后也可能闪烁。当前无法保证常亮，不能仅凭未看到灯判断拍摄已停止。

### 为什么锁屏后的实体拍摄键不能停止？

系统锁屏状态由 Android / Sony 处理按键，应用没有全局监听权限。先解锁回到应用，再全按停止；5 秒后的应用内黑屏可直接全按停止。

### EV 修改了，为什么拍摄中不能再调？

设置在开始前应用并保存。延时任务期间固定参数，避免连续照片突然变化；结束后可重新调整。它不是手动快门或 ISO 输入。

### 4K / 60fps 或 AV1 不可选怎么办？

当前设备可能没有支持该规格、码率和输入格式的编码器。修改视频输出设置，等待重新检测；没有可用编码器时禁止开始需要自动合成的延时拍摄，单张拍照仍可使用。

### 成片没有生成，原片在哪里？

先检查项目列表和 `metadata.json` 的错误。至少两张才生成延时视频；只有一张按照片保存。合成空间不足、编码失败、发布失败或取消时，项目内仍可能保留照片和视频。应用在每次保存照片前检查最低约 100 MiB 可用空间，合成阶段还会检查额外空间。

### 应用被强制结束或手机断电后会自动续拍或续编码吗？

不会自动续拍或续编码。服务采用 `START_NOT_STICKY`，不会从后台擅自重开相机。重新打开应用后，如果项目中至少保留两张照片且尚无视频，可在“设置 → 项目列表”点“生成视频”恢复成片；若原片已被成功合成后的清理流程删除，则无法重新生成。元数据仍显示 running 不代表服务仍在运行。

## 项目结构与运行流程

```text
app/src/main/java/com/xperia/timelapse/
├── camera/       # 相机绑定、设备能力、对焦、光圈、WB / EV 与参数锁定
├── data/         # 项目元数据、照片与视频的 MediaStore 发布
├── power/        # 自动锁屏授权与 30 秒计时
├── service/      # 相机前台服务、通知、唤醒锁与状态协调
├── timelapse/    # 拍摄调度、配置和状态模型
├── ui/           # Compose 取景界面、菜单、黑屏及实体键处理
├── util/         # 存储、权限与时间工具
└── video/        # 编码、YUV 转换、完整校验与安全清理
app/src/test/     # 单元测试
app/src/main/res/ # 图标、文件分享、备份限制和锁屏策略声明
docs/            # 需求、测试步骤及各功能的验证记录
```

Activity 提供预览 Surface、设置和交互；CameraX 相机绑定到 `LifecycleService`，拍摄生命周期由服务持有。调度器使用单调时钟，补偿照片拍摄与落盘耗时；错过时点会跳过，不连续补拍，单次失败最多尝试 3 次。

开始前准备相机参数，准备阶段可停止并设置 15 秒上限。拍摄期间使用 camera 类型前台服务与 CPU 部分唤醒锁。结束后关闭相机，合成阶段切换为 dataSync 类型前台服务进行本地处理；完成后释放资源。

实体键使用 Android 标准的 FOCUS / CAMERA 按键回调。PRO-I 实际观察到半按 `KEYCODE_FOCUS=80 / scanCode=528`，全按 `KEYCODE_CAMERA=27 / scanCode=766`。半按走现有坐标对焦路径，全按通过状态门控和按压状态机防止重复触发。

## 测试与真机验证

当前 **73 项单元测试通过**，`assembleDebug` 和 `lintDebug` 通过。测试覆盖调度与重试、暂停和时长结束、视频编码策略、YUV 转换、输出规格、发布校验、安全清理、WB / EV 的能力归一化、自动锁屏计时，以及实体键长按、取消和焦点丢失等边界。
